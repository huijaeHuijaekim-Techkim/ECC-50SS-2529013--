1장 깃 시작하기

리눅스_명령어
# 1. 디렉터리 탐색 및 확인 명령어

pwd (Print Working Directory): 현재 위치한 디렉터리의 전체 경로(절대 경로) 확인

ls (List): 현재 디렉터리 안의 파일 및 하위 디렉터리 목록 확인

ls -a: 숨김 파일/디렉터리까지 모두 표시 (all)

ls -l: 파일의 상세 정보(권한, 크기, 소유자 등)를 리스트 형태로 표시 (long)

ls -r: 파일 정렬 순서를 거꾸로 표시 (reverse)

ls -t: 파일 작성 시간(내림차순) 기준으로 표시 (time)

Tip: ls -al 처럼 옵션을 여러 개 묶어서 사용 가능!

clear: 터미널 창 화면을 깨끗하게 지우기 (초기화)

# 2. 디렉터리 이동 기호 & 명령어 (cd)

~ : 홈 디렉터리 (사용자의 기본 디렉터리, 터미널 기본 위치)

. : 현재 작업 중인 디렉터리

.. : 현재 위치의 한 단계 상위(바깥) 디렉터리

cd .. : 한 단계 상위 폴더로 이동 (Change Directory)

cd 디렉터리명 : 입력한 하위 디렉터리 안으로 이동 (예: cd Documents)

# 3. 디렉터리 생성 및 삭제

mkdir 디렉터리명 (Make Directory): 현재 위치에 새로운 디렉터리 생성 (예: mkdir test)

rm -r 디렉터리명 (Remove): 디렉터리 삭제. -r 옵션을 붙여야 하위 디렉터리와 내부 파일까지 깔끔하게 싹 지워짐.


2장 
버전_관리_명령어

# 1. 깃 저장소 만들기 및 상태 확인

git init : 현재 머물고 있는 디렉터리를 깃 저장소(Repository)로 초기화.

실행 시 눈에 보이지 않는 .git 숨김 폴더가 생성됨.

터미널 경로 끝에 (main) 또는 (master)라는 브랜치 이름이 표시되기 시작.

git status : 현재 깃 저장소의 상태를 확인하는 가장 중요한 명령어임.

On branch main: 현재 main 브랜치에서 작업 중임을 의미.

No commits yet: 아직 저장소에 기록된 커밋(버전)이 없음.

Untracked files: 깃이 아직 버전 관리를 시작하지 않은 새로운 파일이 존재함을 의미.

Changes to be committed: 스테이지에 파일이 성공적으로 올라가서 커밋을 기다리고 있는 상태.

# 2. 스테이지에 파일 올리기 (Staging)

git add <파일명> : 수정한 파일을 작업 트리에서 스테이지(Staging Area)로 올리는 명령어. (예: git add hello.txt)

실행 후 반드시 git status를 다시 쳐서 글씨가 빨간색(Untracked)에서 초록색(Changes to be committed)으로 변했는지 확인하는 습관을 들이는 것이 좋다.


커밋_및_되돌리기_명령어
# 1. 커밋(Commit) 및 로그 확인 명령어
git commit -m "메시지" : 스테이징한 파일을 입력한 메시지와 함께 커밋(버전 생성)함.
git commit -am "메시지" : 한 번이라도 커밋된 적 있는 파일(Tracked)에 한해, 스테이징(add)과 커밋을 동시에 실행함.  
git log : 지금까지 만든 커밋 내역(커밋 해시, 작성자, 날짜, 메시지 등)을 상세히 확인함.
git diff : 최근 저장된 버전(커밋)과 현재 작업 폴더에서 수정한 파일 사이의 구체적인 차이(코드 변경점)를 보여줌. 

 # 2. 작업 되돌리기 (Undo / Reset)
git restore 파일명 : 작업 트리에서 수정한 파일의 내용을 취소하고 원래 상태로 되돌림. (참고: 예전 버전의 checkout 기능을 대체함)
git restore --staged 파일명 : 스테이지에 올린 파일의 스테이징을 취소(장바구니에서 뺌)함.
git reset HEAD^ : 가장 최근에 한 커밋을 취소하고 파일들을 작업 트리로 되돌림.
git reset 커밋해시 : 지정한 커밋 해시 시점으로 완전히 이동하며, 그 이후에 만들어진 커밋 이력은 모두 삭제함.  git revert 커밋해시 : 지정한 커밋의 변경 이력을 취소하되, 이전 기록을 삭제하지 않고 '취소했다는 내용'을 새로운 커밋으로 남김.

브랜치_명령어
# 1. 브랜치 생성 및 이동

git branch <브랜치명> : 현재 버전을 기준으로 새로운 브랜치를 생성함. (예: git branch fixed)

git branch : 현재 저장소에 만들어진 브랜치 목록을 확인함. (내가 현재 위치한 브랜치 앞에는 * 기호가 붙음)

git switch <브랜치명> : 작업 공간을 입력한 브랜치로 이동(전환)함. (주의: 구 버전 깃에서는 checkout 명령어를 사용했음)

# 2. 브랜치 로그 확인 및 비교

git log --oneline --branches : 모든 브랜치의 최신 커밋 내역을 한 줄씩 깔끔하게 요약해서 보여줌.

git log --oneline --branches --graph : 커밋 간의 부모-자식 관계와 브랜치의 갈라짐/합쳐짐 흐름을 점선(그래프)으로 시각화해서 보여줌.

git log main..apple : 브랜치 간의 차이점을 비교함. (마침표 기준 왼쪽인 main 브랜치에는 없고, 오른쪽인 apple 브랜치에만 있는 커밋을 보여줌)

# 3. 브랜치 병합(Merge) 및 삭제

git merge <가져올브랜치명> : 내가 '현재 위치한 브랜치'에 대상 브랜치의 작업 내용을 가져와서 합침. (예: fixed 브랜치를 main에 합치려면, 먼저 main 브랜치로 이동(switch)한 상태에서 git merge fixed를 실행해야 함)

git cherry-pick <커밋해시> : 지정한 특정 커밋 해시의 작업 내용만 쏙 뽑아와서 현재 브랜치에 합침.

git branch -d <브랜치명> : 병합이 모두 끝나서 더 이상 필요 없는 브랜치를 삭제함. (만약 병합하지 않은 브랜치를 강제로 삭제하고 싶다면 소문자 -d 대신 대문자 -D를 사용함)

원격저장소_및_동기화
# 1. 원격 저장소(GitHub) 연결
git remote add origin <원격저장소URL> : 내 컴퓨터의 지역 저장소와 깃허브의 원격 저장소를 연결함.

참고: origin은 깃허브 원격 저장소를 부르는 기본 별명(관례)임.

git remote -v : 원격 저장소가 내 컴퓨터에 제대로 연결되었는지 주소 목록을 확인함.

# 2. 원격 저장소와 동기화 (Push & Pull)

git push -u origin main : 지역 저장소의 커밋을 맨 처음 원격 저장소로 밀어 올릴 때 사용함.

-u 옵션: 내 컴퓨터의 main 브랜치와 깃허브의 main 브랜치를 영구적으로 연결해 주는 옵션 (처음 한 번만 쓰면 됨).

git push : 한 번 연결해 둔 이후부터는 단순히 이 명령어만 입력해도 원격 저장소로 자동 백업됨.

git pull origin main : 원격 저장소에 있는 최신 커밋 내역을 내 컴퓨터의 지역 저장소로 가져와서 합침.

# 3. SSH 보안 접속 설정

ssh-keygen : 내 컴퓨터에서 안전한 원격 접속을 위한 SSH 키 쌍(프라이빗 키, 퍼블릭 키)을 자동 생성함. (생성된 퍼블릭 키 내용을 깃허브 설정에 등록하여 사용함)
